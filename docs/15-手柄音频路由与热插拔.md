# 15 - 手柄音频路由与热插拔（PS5 DualSense）

> 目标：PS5 手柄（DualSense）通过 USB 连接时，游戏声音走手柄自带声卡；拔掉手柄
> 声音自动回到板载输出（音源热插拔）。振动作为后续项。

---

## 1. 硬件/系统现状

DualSense 通过 USB 接上后，系统里出现多个设备：

- **card 2 = DualSense USB Audio**（手柄自带声卡，可播放）；
- **event2 / js0** = 手柄本体（`capabilities/ff = 7030000`，**支持 rumble**）；
- 另有 Motion Sensors、Touchpad、Headset Jack 等子设备。

系统音频栈是 **PipeWire + pipewire-pulse + wireplumber**（每用户会话服务，socket 在
`/run/user/1000/pipewire-0`）。手柄接上后 **wireplumber 会自动把默认 sink 切到
DualSense**。

re3 音频用 **OpenAL Soft**，其 alsoftrc 全默认（未指定驱动/设备），因此走 PipeWire →
默认 sink。

## 2. 根因：systemd 服务缺少用户会话环境

现象：做成 systemd 服务后，声音**不再**走手柄（时好时坏、重启后失效）。

日志里的决定性证据：

```
[ALSOFT] (EE) Failed to connect PipeWire event context (errno: 112)
```

`errno 112 = EHOSTDOWN`。re3 服务以 `User=pi` 运行，但 **system 服务默认没有用户
会话的 `XDG_RUNTIME_DIR`**，OpenAL 的 PipeWire 后端找不到
`/run/user/1000/pipewire-0`，连接失败 → fallback 到别的后端 → 不跟随 PipeWire 的
默认 sink。这正是“之前手动跑能出声（有完整会话环境），做成服务后失效”的原因。

## 3. 修复（已固化）

三件事，缺一不可：

1. **给服务补 `XDG_RUNTIME_DIR`**，让 OpenAL 能连上用户 PipeWire：
   ```ini
   Environment="XDG_RUNTIME_DIR=/run/user/1000"
   ```
2. **开启 pi 的 linger**，保证开机（无需交互登录）就有用户会话 + PipeWire +
   `/run/user/1000`：
   ```bash
   sudo loginctl enable-linger pi
   ```
3. **排序依赖**，让 re3 在用户会话（PipeWire）就绪后再启动，消除时序竞态：
   ```ini
   After=... user@1000.service
   Wants=user@1000.service
   ```

修复后日志不再有 ALSOFT 错误，re3 作为 PipeWire 客户端出现
（`node.name = "re3"`, `Stream/Output/Audio`），音频流跟随默认 sink。

## 4. 音源热插拔 = PipeWire 默认 sink 跟随

一旦 OpenAL 正常连上 PipeWire，**热插拔是天然的**：

- 插入手柄 → wireplumber 把默认 sink 切到 DualSense → re3 的流迁移到手柄；
- 拔掉手柄 → 默认 sink 回到板载 → re3 的流迁回板载。

依赖 PipeWire 的 `allow-moves`（OpenAL/PipeWire 默认允许迁移活动流）。**无需在
re3 代码里做任何音频设备管理**——这是关键设计取舍：把设备路由交给系统音频栈，
游戏只管产声。

## 5. 固化位置

- 服务文件版本化在仓库 **`deploy/re3.service`**（与 Pi 上 `/etc/systemd/system/
  re3.service` 的有效指令一致）。部署时拷过去，`daemon-reload` + `enable`。
- linger 是一次性系统设置（`loginctl enable-linger pi`）。

## 6. 待办：手柄振动（force feedback）

尚未实现。现状与方案：

- re3 的震动意图存在 `CPad::GetPad(0)->ShakeDur`（时长 ms）/ `ShakeFreq`（强度）。
  目前只有 **Switch (libnx)** 分支消费它（`_psHandleVibration`，gbm.cpp）；evdev
  路径**没有**振动代码。
- DualSense 的 event 节点支持 `FF_RUMBLE`（`capabilities/ff` 非零）。
- 计划：evdev 输入后端把手柄节点用 **`O_RDWR`** 打开（当前是 `O_RDONLY`），用
  `EVIOCSFF` 上传一个 `FF_RUMBLE` 效果，每帧根据 `ShakeDur/ShakeFreq` 通过写
  `input_event(EV_FF, effect_id, on/off)` 播放/停止。热插拔时随设备增删重传效果。
- 注意上游有 `Fix endless vibration in pause menu` 的先例，暂停/失焦时要停振动。
