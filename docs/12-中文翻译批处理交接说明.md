# 12 - 中文翻译批处理交接说明

本文档给“执行翻译的模型/协作者”看。目标：把 GTA3 全量英文文本翻译成简体中文，
沉淀到 fork 的 GXT 仓库（`FASTSHIFT/GXT` 的 `III PC/chinese.txt`），再由本仓工具
生成 `CHINESE.GXT` + 像素字体图集供 re3 使用。整体方案见 `docs/11`。

## 你要做什么（一句话）

读取 `spike/batches/batch_NN.json`（英文），逐条翻译成简体中文，写到
`spike/batches/batch_NN.zh.json`（key 不变、只改值），NN 从 `001` 到 `013`。
`batch_000` 已翻好，作为格式样例，不用重做。

## 文件位置

- 输入批次：`spike/batches/batch_000.json` … `batch_013.json`（每批约 200 条）
- 提示词：`spike/batches/PROMPT.txt`（与下方“翻译提示词”一致）
- 样例产物：`spike/batches/batch_000.zh.json`（照此格式产出）
- 源文本（校验/回退用）：`spike/american.txt`（Sergeanur/GXT 的 III PC/american.txt）

## 输入/输出格式

输入 `batch_NN.json`：
```json
{
 "IN_VEH": "~g~Hey! Get back in the vehicle!",
 "HELP4_A": "Press the~h~ ~k~~VEHICLE_ACCELERATE~ button~w~ to ~h~accelerate."
}
```

输出 `batch_NN.zh.json`（相同 key，值换成中文，控制符原样保留）：
```json
{
 "IN_VEH": "~g~嘿！回到车上来！",
 "HELP4_A": "按~h~ ~k~~VEHICLE_ACCELERATE~ 键~w~来~h~加速。"
}
```

## 翻译提示词（逐字使用）

> 你正在把《侠盗猎车手3》(GTA III) 的游戏内文本翻译成简体中文，用于一个爱好者
> 移植版。输入是一个 JSON 对象，key 为字符串标识，value 为英文原文。请输出一个
> **相同 key** 的 JSON 对象，每个 value 是对应英文的简体中文翻译。
>
> 硬性规则（违反任意一条都会让游戏出错）：
> 1. 保持每个 key 原样。不要增删、改名或重排 key。
> 2. 原样保留所有控制符，位置不变：如 `~g~ ~w~ ~h~ ~r~ ~b~ ~y~ ~p~ ~1~ ~k~`，
>    以及按键占位如 `~k~~VEHICLE_ACCELERATE~`。绝不翻译、删除、重排，或在其内部
>    加空格。它们可能出现在开头、中间或结尾，保持其相对文字的确切位置。
> 3. 不要翻译 `~k~...~` 里的全大写占位符（如 `~VEHICLE_ENTER_EXIT~`），原样保留。
> 4. 只输出合法 JSON 对象，UTF-8，无注释、无 markdown 代码围栏。
> 5. 译文尽量简短——这是给 320×240 小屏用的。用自然的游戏中文
>    （如 `WASTED`→`死亡`，`BUSTED`→`被捕`）。
> 6. 专有名词：知名的地名/人名用 GTA3 通用中文译法，否则保留英文原名。
> 7. 若某值为空、或仅含控制符/标点，原样返回。
> 8. 以下特殊 key 不要翻译，值原样复制：`LETTER1`（字体字符集定义）、
>    `DEFNAM`（默认主角名）；以及任何纯 ASCII 字母/横线、没有实义单词的值。
>
> 示例输入：
> `{"1001": "BUSTED", "HELP2_A": "Press the ~h~/ button~w~ when running to ~h~sprint."}`
> 示例输出：
> `{"1001": "被捕", "HELP2_A": "奔跑时按 ~h~/ 键~w~可以~h~冲刺。"}`

## 术语约定（建议统一）

| 英文 | 中文 |
|------|------|
| WASTED | 死亡 |
| BUSTED | 被捕 |
| 8-Ball | 8球 |
| Misty | 米丝蒂 |
| Luigi | 路易吉 |
| Liberty City | 自由城 |
| 控制符 ~g~/~r~/~b~/~y~/~p~/~w~/~h~ | 原样保留（颜色/高亮） |
| ~1~ 等数字占位 | 原样保留 |
| ~k~~ACTION~ | 原样保留（按键图标） |

（不确定的人名/地名保留英文即可，后续可统一校订。）

## 校验与合并（翻译完成后，由本仓维护者执行）

```bash
# 合并所有 batch_NN.zh.json -> 上游格式 chinese.txt（沉淀进 fork GXT 仓库），
# 同时校验每条控制符与英文一致（不一致会告警），漏翻的自动回退英文保证完整。
python3 tools/make_translation_batches.py merge spike/american.txt \
    --outdir spike/batches --out "" --out-txt "spike/GXT/III PC/chinese.txt"

# 由 chinese.txt 生成 re3 用的 GXT + Zpix 像素字体图集
python3 tools/gen_cn_font.py "spike/GXT/III PC/chinese.txt" \
    --font spike/zpix.ttf --out-gxt CHINESE.GXT --out-png fonts_c.png \
    --cell 16 --px 12 --cols 64
```

`merge` 输出的 `III PC/chinese.txt` 直接 `git add` 提交到 fork 的 GXT 仓库即可，
翻译成果长期保存、可协作、也能被上游 `gxt.exe` 编译。

## 质量校验清单

- 控制符 warning 数应为 0（merge 会打印 `N code warnings`）。若非 0，检查对应 key
  的中文是否漏了/多了某个 `~x~`。
- 漏翻数（`fell back to English`）应随批次完成逐步降到接近 0（LETTER1/DEFNAM 等
  特殊项本就保留英文/原值，属正常）。
- 生成日志里的 `unique CJK glyphs` 数即图集字数；随翻译完成会增长到 ~2000-3000，
  图集约 2048×2048 以内，属正常。
