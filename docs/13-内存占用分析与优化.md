# 13 - 内存占用分析与优化

> 目标平台：Raspberry Pi Zero 2 W（512MB LPDDR2，可用 ~424MB），headless SPI。
> 现象：长时间游玩后系统内存使用率涨到 ~90%，但 re3 的 RSS 看起来占比不大。

---

## 1. 诊断

在 Pi 上抓取内存全貌（`free`、`/proc/meminfo`、按 RSS/Swap 排序的进程）后发现：

| 指标 | 值 | 说明 |
|---|---|---|
| MemTotal | ~424MB | 512MB 物理内存扣除 GPU/内核预留后可用量 |
| re3 VmRSS | ~13.8MB | 常驻物理内存（看着小） |
| re3 VmData | ~130MB | 堆/数据段（真实占用大头，随游玩增长） |
| re3 VmSwap | ~57MB（4 分钟时） | 已被压入 zram 的部分 |

**结论：`re3` 才是内存占用的真正大头。** RSS 小只是假象——世界流式加载
（模型/纹理）让堆持续增长，其中的冷页被换进 zram，所以 RSS 显得不高，而实际
占用（RSS + Swap）一直在涨。后台服务不是“越玩越涨”的根因。

## 2. swap 现状（重要更正）

一开始误判 swap 在 SD 卡上（因为该系统没有 `swapon` 命令）。实际 `/proc/swaps`
显示 swap 就是 **zram**（`/dev/zram0`），由 `systemd-zram-generator` 管理，而且
配置本就良好：

- 压缩算法：**zstd**（压缩率最佳），无需更换。
- 容量：~424MB（≈ 物理内存）。
- 实测压缩比 **≈ 2.7:1**：约 77.8MB 换出数据只真正占用 ~31.8MB 物理内存
  （数据来自 `/sys/block/zram0/mm_stat`）。

即被换出的数据经 zstd 压缩后只占约 1/3 内存，等于变相扩容，且不触碰 SD 卡。

## 3. 已实施的优化

### A. 关闭对掌机无用的后台服务（可逆）

停用并 `disable`（socket 激活的一并 `mask`，防止被重新唤醒）：

| 服务 | 作用 | 处理 |
|---|---|---|
| `nfs-blkmap` | NFS 块映射 | disable |
| `rpcbind`(+socket) | RPC 端口映射（NFS 依赖） | disable + mask socket |
| `avahi-daemon`(+socket) | 局域网 mDNS 服务发现 | disable + mask socket |
| `udisks2` | 可插拔磁盘自动挂载 | disable |
| `accounts-daemon` | 桌面登录账户管理 | disable |

**保留**：`bluetooth`（手柄）、`NetworkManager` + `wpa_supplicant`（WiFi）、
`ssh`、`cron`、`systemd-timesyncd`（对时）、`re3`。
`polkit` 为 `static`（被依赖拉起），不单独处理。

单个服务省下的 RSS 多为几 MB 量级，累加加上减少后台唤醒对这台小机器有意义，但
**并非“越玩越涨”的根因**。

回退命令：

```bash
sudo systemctl unmask rpcbind.socket avahi-daemon.socket
sudo systemctl enable --now nfs-blkmap rpcbind avahi-daemon udisks2 accounts-daemon
```

### B. zram 调优：提高 vm.swappiness

zram 换出成本远低于磁盘 swap，因此更积极地把冷页压进 zram、给游戏活跃数据腾出
物理内存是有利的。将 `vm.swappiness` 从默认 60 提高到 **100** 并持久化：

```
# /etc/sysctl.d/99-zram-swappiness.conf
vm.swappiness=100
```

即时生效：`sudo sysctl -w vm.swappiness=100`。

## 4. 待观察 / 后续

- **re3 堆增长是否为泄漏**：仅采样了运行 4 分钟的数据，尚无法区分“正常流式加载
  到稳态”与“持续泄漏”。建议正常游玩 20–30 分钟后再次采样 `VmData/VmRSS/VmSwap`，
  看是否趋于稳态。
- 若确认是流式加载到稳态：配合 zram + 高 swappiness，90% 更多是“内存被高效利用”
  而非危险信号；真正要警惕的是 OOM 或卡顿。
- 若确认持续增长：需在 re3 侧排查流式管理（模型/纹理 streaming 的驻留上限）。
- `/tmp`、`/dev/shm` 均为 213MB tmpfs（吃内存），当前用量极低（几 MB），留意别有
  组件往里大量写入。

## 5. 采样命令备忘

```bash
# 内存全貌
free -h; grep -E 'MemTotal|MemAvailable|Cached|Slab' /proc/meminfo
# 进程 RSS 排名
ps -eo pid,comm,rss --sort=-rss | head
# 各进程 swap 占用
for p in $(ls /proc | grep -E '^[0-9]+$'); do \
  awk -v pid=$p '/VmSwap/{print $2, pid}' /proc/$p/status 2>/dev/null; \
done | sort -rn | head
# zram 压缩效果： orig  compr  mem_used ...
cat /sys/block/zram0/mm_stat
# re3 内存明细
grep -E 'VmRSS|VmSwap|VmData|VmSize' /proc/$(pgrep re3)/status
```
