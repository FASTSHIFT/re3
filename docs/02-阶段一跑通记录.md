# 02 - 阶段一跑通记录

> 记录 re3 在树莓派 Zero 2 W 上首次成功运行的完整过程、关键问题与实测数据。

## 1. 里程碑结论

**阶段一（最快跑通）成功。** re3 在树莓派 Zero 2 W 上：

- ✅ 出画面，稳定运行（实测连续 180s / 交互 10min 无崩溃）
- ✅ 走 **VideoCore IV 硬件 GLES 2.0**（非软件 llvmpipe）
- ✅ 内存峰值仅约 88MB（512MB 完全够用）
- ✅ 帧率体感良好（轻场景/菜单流畅，符合"瓶颈在填充率而非算力"的判断）

## 2. 关键问题与解决

### 2.1 拿到的是软件 GL 而非硬件 GLES

**现象**：首次运行日志显示 `OpenGL version: 2.1 Mesa` + `GLFW Error: EGL: Failed to create context`。

**根因**：`vendor/librw/src/gl/gl3device.cpp` 的上下文 profile 尝试顺序把桌面 GL 排在 GLES 前：

```cpp
static struct { int gl; int major, minor; } profiles[] = {
    { GLFW_OPENGL_API, 3, 3 },   // 桌面 GL
    { GLFW_OPENGL_API, 2, 1 },   // ← XWayland/llvmpipe 软件 GL 先命中
    { GLFW_OPENGL_ES_API, 3, 1 },
    { GLFW_OPENGL_ES_API, 2, 0 },// 真正想要的硬件 GLES 排在最后
    ...
};
```

XWayland 提供的软件 GL 2.1 先创建成功，librw 就用了它，轮不到硬件 GLES。

**解决**：加 `RPI_PREFER_GLES` 宏，让 GLES 优先：

```cpp
#ifdef RPI_PREFER_GLES
    { GLFW_OPENGL_ES_API, 2, 0 },
    { GLFW_OPENGL_ES_API, 3, 1 },
    { GLFW_OPENGL_API, 3, 3 },
    { GLFW_OPENGL_API, 2, 1 },
#else
    ...原顺序...
#endif
```

改后日志变为 `OpenGL version: OpenGL ES 2.0 Mesa 25.0.7`，EGL 错误消失。

### 2.2 GLFW 依赖桌面显示服务器

**现象**：停桌面（lightdm）后 gdb 显示 `gl3device.cpp:1666: Error: glfwInit() failed`。

**结论**：GLFW 是 X11 后端编译的，必须有 X server（XWayland）。当前系统是纯 Wayland（labwc），XWayland 按需启动。

**含义**：GLFW 路线必须**开着桌面**跑（经 XWayland）。若要脱离桌面全屏（省内存 + 直接 KMSDRM 硬件），需走 SDL2 路线（阶段三）。

### 2.3 SSH 会话被游戏高负载挤死

**现象**：前台 SSH 跑游戏时，SSH 命令超时、甚至 "No route to host"。

**真相**：不是崩溃，是游戏全屏 + 高负载把 SSH 响应挤没了。用 `setsid` 完全脱离 SSH 会话后台运行 + 日志落盘，问题解决。

## 3. 运行方式（当前）

```bash
# 树莓派上（需开着桌面，经 XWayland）
cd ~/re3game
export DISPLAY=:0
export XDG_RUNTIME_DIR=/run/user/1000
./re3
```

SSH 远程验证用 `setsid` 脱离会话 + 日志落盘：

```bash
setsid bash -c "cd ~/re3game && export DISPLAY=:0 XDG_RUNTIME_DIR=/run/user/1000 && \
  timeout 600 ./re3 > /tmp/re3.log 2>&1; echo DONE > /tmp/re3.done" < /dev/null &
```

## 4. 实测数据

| 项 | 数值 |
|---|---|
| 二进制大小（strip 后） | 2.6 MB |
| 渲染器 | VC4 V3D 2.1 (OpenGL ES 2.0 Mesa 25.0.7) |
| 内存峰值 (RSS) | ~88 MB（默认画质） |
| 稳定性 | 连续 180s / 交互 10min 无崩溃，优雅退出 |
| 资源占用 | ~1.3 GB (~/re3game) |

### 4.1 内存观察：高画质压力在显存(CMA)而非进程

调高画质时的实测：

- **re3 进程 RSS 峰值仍约 88MB**（进程本身内存不涨）。
- **但系统整体可用内存从 ~235MB 掉到 ~41MB**（used 383/424MB）。

**结论**：高画质的内存压力转移到 **GPU 侧 CMA/显存**（更大 framebuffer + 纹理），这部分不计入进程 RSS，但吃系统总内存。这印证了 Zero 2 W 的 512MB 在高画质下的真正瓶颈是**显存/CMA**，而非 CPU 内存或进程占用。降分辨率不仅省填充率，也直接省 CMA。

## 6. 成果固化

- `vendor/librw/src/gl/gl3device.cpp`：profile 顺序加 `RPI_PREFER_GLES` 分支。
- `CMakeLists.txt`：新增 `RE3_RPI` 选项，开启时全局定义 `RPI_PREFER_GLES`。
- `rpi-armhf-toolchain.cmake`：交叉编译工具链文件。

启用方式：

```bash
cmake -S . -B build-rpi -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=$(pwd)/rpi-armhf-toolchain.cmake \
  -DCMAKE_BUILD_TYPE=Release -DRE3_AUDIO=OAL \
  -DRE3_VENDORED_LIBRW=ON -DLIBRW_PLATFORM=GL3 -DLIBRW_GL3_GFXLIB=GLFW \
  -DRE3_RPI=ON -DLIBRW_TOOLS=OFF -DLIBRW_INSTALL=OFF
```
