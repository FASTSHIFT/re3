# 17 - 部署指南（交叉编译 → 树莓派 ST7789 SPI 掌机）

> 把 re3 的 **ST7789 SPI 屏版本**从开发主机交叉编译，部署到目标树莓派并做成
> 开机自启。本文是正式的、可照做的完整流程，汇总并取代散落在
> docs/01、06、08、15 里的部署片段。
>
> 目标形态：Raspberry Pi Zero 2 W + 2 寸 ST7789 SPI 屏（GamePi20），无桌面、
> GBM/EGL 离屏渲染 → SPI 推屏，evdev/GPIO 输入。其他开发板（Pi 4/5）思路一致，
> 见 [docs/08 平台解耦方案](08-平台解耦方案.md)。

约定：下文所有命令里的 `<PI_HOST>`（主机名或地址）、`<PI_USER>`（登录用户，
默认 `pi`）、`<GAME_DIR>`（Pi 上的游戏资源目录，如 `~/re3game`）均为占位符。

---

## 0. 前置条件

### 开发主机（交叉编译）

- armhf 交叉工具链：`arm-linux-gnueabihf-gcc` / `arm-linux-gnueabihf-g++`
- `cmake`（≥3.10）、`ninja`
- 从目标 Pi 同步来的 **sysroot**（含 EGL/GBM/GLESv2/OpenAL/mpg123 等 armhf 开发库）
- 部署用工具：`ssh`、`scp`（或 `rsync`）

sysroot 同步方式见 [docs/01](01-现状分析与移植计划.md)：

```bash
mkdir -p rpi-sysroot/usr/include rpi-sysroot/usr/lib
rsync -az --rsync-path="sudo rsync" <PI_USER>@<PI_HOST>:/usr/include/ rpi-sysroot/usr/include/
rsync -az --rsync-path="sudo rsync" <PI_USER>@<PI_HOST>:/usr/lib/     rpi-sysroot/usr/lib/
ln -sfn usr/lib rpi-sysroot/lib   # usr-merge，解决 libc.so 链接脚本绝对路径
```

在 `rpi-armhf-toolchain.cmake` 里把 `RPI_SYSROOT` 指向该 sysroot（或配置时传
`-DRPI_SYSROOT=...`）。

### 目标树莓派

- 一份**自备的正版 GTA III** 游戏资源（本仓库不含任何游戏资源）。
- 已接好 ST7789 SPI 屏，接线见 [drivers/st7789/README.md](../drivers/st7789/README.md)。
- 可 SSH 登录。

## 1. 交叉编译

```bash
cmake -S . -B build-spi -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=$(pwd)/rpi-armhf-toolchain.cmake \
  -DCMAKE_BUILD_TYPE=Release \
  -DLIBRW_PLATFORM=GL3 -DLIBRW_GL3_GFXLIB=GBM \
  -DRE3_AUDIO=OAL -DRE3_RPI=ON \
  -DRE3_OUTPUT_SPI=ON -DRE3_INPUT_EVDEV=ON \
  -DRE3_CHINESE=ON \
  -DRE3_VENDORED_LIBRW=ON -DLIBRW_TOOLS=OFF -DLIBRW_INSTALL=OFF

cmake --build build-spi -j$(nproc)
```

产物：`build-spi/src/re3`（armhf ELF）。

### 关键构建选项

| 选项 | 作用 |
|---|---|
| `LIBRW_GL3_GFXLIB=GBM` | 用 GBM/EGL 离屏渲染后端（无桌面），编译 `src/skel/gbm` 而非 glfw |
| `RE3_OUTPUT_SPI=ON` | 输出后端选 ST7789 SPI，把 `drivers/st7789` 编进 re3 |
| `RE3_INPUT_EVDEV=ON` | evdev 键鼠/手柄输入（`RE3_RPI=ON` 时默认已开）|
| `RE3_RPI=ON` | Pi 优化：优先 GLES2、LTO、提速编译选项、精简后处理 |
| `RE3_CHINESE=ON` | 简体中文本地化（可选）|

> **关于 `RE3_STRICT_WARNINGS`**：默认 `OFF`。自有代码（`src/skel/gbm`、
> `drivers/st7789`）以 `-Werror` 编译保证零警告，但它们会 include 上游 re3 那些
> 不符合 `-Wpedantic` 的头文件；默认严格会导致这些头文件触发 `-Werror` 而编译
> 失败。保持默认 `OFF` 即可正常构建。想审查全部警告时再显式传
> `-DRE3_STRICT_WARNINGS=ON`。

CI 里对应的构建见 `.github/workflows/build-rpi.yml` 的 `rpi` job（用系统 armhf
dev 包 + `-DRPI_SYSROOT=""`，供参考）。

## 2. 目标 Pi 一次性配置

每块新板子/新系统镜像**只需做一次**。用仓库自带的一键脚本
[`drivers/st7789/setup_pi.sh`](../drivers/st7789/setup_pi.sh)：

```bash
scp drivers/st7789/setup_pi.sh <PI_USER>@<PI_HOST>:~/
ssh <PI_USER>@<PI_HOST>
sudo ./setup_pi.sh          # bufsiz=65536, core_freq=400（Pi Zero 2 W）
sudo reboot                 # SPI / bufsiz / core_freq 需重启生效
```

脚本做的事（细节与原理见 [docs/06 §5.6](06-ST7789-SPI推送优化分析.md) 与
[drivers/st7789/SETUP.md](../drivers/st7789/SETUP.md)）：

| # | 配置 | 位置 | 为什么 |
|---|---|---|---|
| 1 | `dtparam=spi=on` | config.txt | 创建 `/dev/spidev0.0`，没有它就没有 SPI 设备 |
| 2 | `spidev.bufsiz=65536` | cmdline.txt | 默认 4096，单次传输超过会 EMSGSIZE 失败 |
| 3 | `core_freq=400` + `core_freq_min` | config.txt | SPI 实际时钟 = core_freq/偶数分频，不锁会漂 |
| 4 | CPU governor = `performance` | systemd unit | **性能最大单因子**：ondemand 会在 SPI DMA 空闲期降频，吞吐掉 ~40% |
| 5 | 用户加入 `gpio`、`spi` 组 | usermod | 免 root 访问 `/dev/gpiomem`、`/dev/spidev` |

重启后自检：

```bash
ls -l /dev/spidev*                                   # 期望 /dev/spidev0.0
cat /sys/module/spidev/parameters/bufsiz             # 期望 65536
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor  # 期望 performance
```

### 2.1 SPI 时钟上限（换屏/换排线时）

不同面板+排线的稳定 SPI 上限不同。用诊断图案连续重刷判定（抖动=不稳）：

```bash
./st7789_pattern 100000000 -1   # 连续重刷；有杂色跳动=不稳
./st7789_pattern 80000000  -1   # → 实际 66.7MHz；纹丝不动=安全
```

取「纹丝不动」的最高档写进驱动配置。本项目实测面板稳定上限为**请求 80MHz
（实际 66.7MHz，core_freq/6）**；100MHz 会花屏。详见
[docs/06 §5.7](06-ST7789-SPI推送优化分析.md)。

## 3. 部署二进制与资源

游戏资源目录（`<GAME_DIR>`，如 `~/re3game`）应包含你自备的正版 GTA III 文件
（`data/`、`models/`、`audio/`、`anim/`、`TEXT/` 等）。把编译好的二进制放进去：

```bash
# 建议保留旧二进制备份
ssh <PI_USER>@<PI_HOST> 'cp <GAME_DIR>/re3 <GAME_DIR>/re3.bak 2>/dev/null || true'

scp build-spi/src/re3 <PI_USER>@<PI_HOST>:<GAME_DIR>/re3

# 校验一致性
md5sum build-spi/src/re3
ssh <PI_USER>@<PI_HOST> 'md5sum <GAME_DIR>/re3'
```

### 手动试跑（正式做服务前先验证一次）

GBM 后端要独占 DRM，先停桌面再前台跑，看日志：

```bash
ssh <PI_USER>@<PI_HOST>
sudo systemctl stop lightdm       # 释放 DRM（若在跑桌面）
cd <GAME_DIR>
DISPLAY= XDG_RUNTIME_DIR=/run/user/$(id -u) ./re3
```

日志里应看到这些健康标志：

```
spi: ST7789 320x240 (double-buffered)
output sink: spi
evdev: ... gamepad ...
gpio: input ready
... gGameState = GS_FRONTEND     → 进主菜单
... gGameState = GS_PLAYING_GAME → 进游戏
```

`Ctrl-C` 退出。确认没问题再进第 4 步固化。

## 4. 开机自启（systemd 服务）

仓库里 [`deploy/re3.service`](../deploy/re3.service) 是服务模板。**按你的实际
`<GAME_DIR>` 与二进制名改好 `WorkingDirectory`、`ExecStart` 后**再安装。一个可用
的样例：

```ini
[Unit]
Description=GTA3 re3 (ST7789 SPI headless)
After=network.target sound.target user@1000.service
Wants=user@1000.service sound.target
# 关键：让 systemd 接管 DRM——启动 re3 时自动停桌面，无需运行时 polkit 授权
Conflicts=lightdm.service
After=lightdm.service

[Service]
Type=simple
User=<PI_USER>
WorkingDirectory=<GAME_DIR>
Environment="DISPLAY="
Environment="RE3_HUD=1"
# OpenAL/PipeWire 需要用户会话的 runtime dir 才能跟随默认音频 sink（见 docs/15）
Environment="XDG_RUNTIME_DIR=/run/user/1000"
ExecStartPre=-/usr/bin/amixer -c 0 sset PCM 80%
ExecStart=<GAME_DIR>/re3
StandardOutput=append:/home/<PI_USER>/re3spi.log
StandardError=append:/home/<PI_USER>/re3spi.log
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

安装与启用：

```bash
scp deploy/re3.service <PI_USER>@<PI_HOST>:~/re3.service
ssh <PI_USER>@<PI_HOST>
sudo cp ~/re3.service /etc/systemd/system/re3.service
loginctl enable-linger <PI_USER>     # 让用户会话在开机时就存在（音频依赖，一次性）
sudo systemctl daemon-reload
sudo systemctl enable re3.service
sudo systemctl start re3.service
```

### 要点说明

- **`Conflicts=lightdm.service`**：这是让桌面把 DRM 让给 re3 的推荐做法。用
  `ExecStartPre=systemctl stop lightdm` 在服务上下文里会因缺 polkit 授权而失败；
  `Conflicts` 由 systemd 作业调度处理，启动 re3 自动停 lightdm，无需授权。
- **`loginctl enable-linger`**：没有它，开机无交互登录时用户会话 `user@1000`
  和 `/run/user/1000` 不存在，OpenAL 的 PipeWire 后端连不上，手柄没声音
  （见 [docs/15](15-手柄音频路由与热插拔.md)）。
- **音频那条 `ExecStartPre` 是非致命的**（前缀 `-`）。若默认声卡不是 card 0
  （例如走 DualSense 手柄音频路由），它会失败但不影响游戏启动，可忽略或删掉。

### 常用运维命令

```bash
sudo systemctl status re3.service       # 状态
sudo systemctl restart re3.service      # 重启
sudo systemctl stop re3.service         # 停止
tail -f /home/<PI_USER>/re3spi.log      # 跟日志
```

## 5. （可选）CPU 超频

Pi Zero 2 W 默认 arm_freq=1000。可超到 1.2GHz 提升 CPU 瓶颈下的帧率
（本项目 CPU 是主要瓶颈，见 [docs/09](09-性能分析报告-CPU瓶颈与优化路径.md)）。

> ⚠️ 超频是硬件层修改，会增加发热与功耗，稳定性取决于个体芯片、供电与散热。
> 请确保供电充足、有散热，并在超频后实测稳定性。

在 `/boot/firmware/config.txt` 里（改前先备份）：

```
arm_freq=1200
over_voltage=6
```

重启后验证：

```bash
vcgencmd get_config arm_freq      # 期望 1200
vcgencmd measure_clock arm        # 期望 ~1200000000
vcgencmd get_throttled            # 期望 0x0（非 0 表示欠压/降频）
vcgencmd measure_temp             # 满载留意勿接近 80℃（会触发降频）
```

`get_throttled` 非 0、花屏或重启不稳，说明供电/散热不足或此芯片超频余量小：
调高 `over_voltage`（如 8）或回退 `arm_freq`。

## 6. 升级已部署版本

改代码后重新部署的最短路径：

```bash
cmake --build build-spi -j$(nproc)                          # 1. 重新编译
ssh <PI_USER>@<PI_HOST> 'sudo systemctl stop re3.service'   # 2. 停旧的
scp build-spi/src/re3 <PI_USER>@<PI_HOST>:<GAME_DIR>/re3    # 3. 覆盖二进制
ssh <PI_USER>@<PI_HOST> 'sudo systemctl start re3.service'  # 4. 起新的
```

## 7. 排障速查

| 现象 | 可能原因 / 处理 |
|---|---|
| 屏幕全黑、无背光 | 多为 `bufsiz` 被重置回 4096（重刷镜像后常见）→ 重跑 `setup_pi.sh`；检查接线与 `cfg.spi_hz` |
| 画面抖动/花屏 | SPI 时钟过高 → 用 `st7789_pattern <hz> -1` 找稳定档，降到 80MHz(→66.7) |
| 帧率莫名卡在 ~50fps | CPU governor 是 ondemand → 确认 `performance`（`setup_pi.sh` 已固化） |
| 起不来、抢不到 DRM | 桌面（lightdm）占着 → 确认服务里有 `Conflicts=lightdm.service` |
| 手柄没声音 | 缺 `loginctl enable-linger` 或 `XDG_RUNTIME_DIR` 未设（见 docs/15） |
| `Message too long` / EMSGSIZE | `spidev.bufsiz` 太小 → 设 65536 并重启 |
| SPI 实际时钟对不上请求值 | core_freq 量化：实际 = core_freq/偶数分频；锁 core_freq，请求能整除的值 |

日志固定在 `/home/<PI_USER>/re3spi.log`（服务模式），或前台运行时的标准输出。
